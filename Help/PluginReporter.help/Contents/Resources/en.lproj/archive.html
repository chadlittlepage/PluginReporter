Archive & Restore

Backup and protect your Plugin Reporter data

Overview

The Archive & Restore feature provides a complete backup solution for all your Plugin Reporter data. Create encrypted archives of your ratings, tags, notes, playlists, and preferences, and restore them on any Mac.

Why Backup?
  • Protect years of ratings and organizational work
  • Move to a new computer seamlessly
  • Recover from accidental deletions
  • Share your plugin setup with collaborators
  • Keep historical snapshots of your plugin library

What Gets Archived

A Plugin Reporter archive contains:

Data Type Description
⭐ Ratings All star ratings you've assigned to plugins
🏷️ Tags Custom tags and tag assignments
📝 Notes Personal notes for each plugin
🎵 Playlists All imported DAW projects and custom playlists
📊 Metadata Custom plugin metadata and user edits
⚙️ Preferences App settings and preferences
Note: The archive does NOT include the actual plugin files themselves - only your organizational data and metadata. Plugin files must be reinstalled separately.

Creating an Archive

Step-by-Step

  1. Choose Plugin Reporter > Settings (or press ⌘,)
  2. Scroll to the Backup & Restore section
  3. Click Export Archive
  4. Choose whether to encrypt with a password (highly recommended)
  5. If encrypting, enter and confirm your password
  6. Choose a save location
  7. Click Export
Important Password Information:
  • If you encrypt your archive, you MUST remember the password
  • There is no password recovery - lost passwords = lost archive
  • Use a strong, unique password
  • Consider using a password manager
  • Store the password separately from the archive file

Encryption

Why Encrypt?

Encryption protects your data if:

  • You store the archive in cloud storage (Dropbox, iCloud Drive, etc.)
  • You share your computer or backups with others
  • The archive contains sensitive notes or project information
  • You want maximum security for your data

Encryption Technology

Plugin Reporter uses industry-standard AES-256-GCM encryption:

  • AES-256 - Advanced Encryption Standard with 256-bit keys
  • GCM Mode - Galois/Counter Mode for authenticated encryption
  • PBKDF2 - Password-Based Key Derivation with 100,000 iterations
  • SHA256 - Secure hash algorithm for key generation
  • Random Salt - Unique salt for each archive prevents rainbow table attacks
Technical Note: This is the same encryption technology used by banks, governments, and security-conscious organizations worldwide. Your data is as secure as your password.

Unencrypted Archives

You can also create unencrypted archives if:

  • The data is not sensitive
  • You want to inspect the archive contents manually
  • You're storing the archive in a secure location

Unencrypted archives are standard ZIP files that can be opened by any ZIP utility.

Restoring from an Archive

Step-by-Step

  1. Choose Plugin Reporter > Settings
  2. Scroll to Backup & Restore
  3. Click Import Archive
  4. Select your .pluginreporter archive file
  5. If encrypted, enter the password when prompted
  6. Review the archive contents and metadata
  7. Choose Replace All Data or Merge with Existing
  8. Confirm the import
  9. Plugin Reporter will restart to load the restored data

Merge vs. Replace

When restoring, you have two options:

Mode What Happens Best For
Replace All Completely overwrites all current data with archive contents New computer setup, starting fresh, recovering from data loss
Merge Combines archive data with current data (archive takes precedence for conflicts) Syncing between computers, selective restoration, adding historical data
Before Restoring: Consider creating a backup of your current data first! Once you replace your data, the previous state is lost unless you have another backup.

Archive Management

Naming Conventions

Plugin Reporter automatically names archives with the date:

Plugin Reporter Backup 1/20/25.pluginreporter

Consider adding descriptive names for different purposes:

  • Plugin Reporter - Studio Mac - 2025-01-20.pluginreporter
  • Plugin Reporter - Before Migration.pluginreporter
  • Plugin Reporter - Monthly Backup Jan 2025.pluginreporter

Storage Locations

Recommended places to store archives:

☁️ Cloud Storage

iCloud Drive, Dropbox, Google Drive (use encryption!)

💾 External Drive

USB drive, SSD, NAS

🖥️ Time Machine

Included in macOS backups automatically

📧 Email

Email to yourself (encrypted archives only)

Backup Schedule

How often should you create archives?

  • Weekly - If you're actively rating and organizing plugins
  • Monthly - For regular maintenance
  • Before major changes - New computer, OS upgrade, bulk edits
  • After importing many projects - Don't lose that work!
Pro Tip: Keep multiple archive versions with dates. Disk space is cheap, and you never know when you'll need to go back to an earlier state.

Use Cases

New Computer Setup

Moving to a new Mac? Here's the workflow:

  1. On old Mac: Create an encrypted archive
  2. Transfer archive to new Mac (USB drive, cloud, AirDrop, etc.)
  3. On new Mac: Install Plugin Reporter
  4. Restore the archive (choose "Replace All")
  5. All your ratings, tags, notes, and playlists are back!

Syncing Multiple Computers

Keep your studio and laptop in sync:

  1. On Studio Mac: Create an archive, save to cloud storage
  2. On Laptop: Import the archive (choose "Merge")
  3. Work on laptop, create new archive when done
  4. Back on Studio Mac: Import laptop archive (choose "Merge")
iCloud Sync: Plugin Reporter also supports automatic iCloud sync for ratings, tags, and notes. Enable in Settings > General > iCloud Sync. Archives provide an additional backup layer and are useful for full data portability.

Collaboration

Share your plugin setup with collaborators:

  1. Create an unencrypted archive (or share password securely)
  2. Send archive to collaborator
  3. They import (choose "Merge" to keep their own ratings)
  4. Now you both have the same playlist and plugin organization

Disaster Recovery

Accidentally deleted all your ratings?

  1. Locate your most recent archive
  2. Import it (choose "Replace All")
  3. Plugin Reporter restarts with your data restored
  4. Crisis averted! 🎉

Archive File Format

File Structure

Plugin Reporter archives (.pluginreporter) are ZIP files containing:

  • manifest.json - Archive metadata and inventory
  • data.json - All ratings, tags, notes, playlists, and preferences

If encrypted, the contents are:

  • encrypted.bin - AES-256 encrypted data bundle
  • salt - Random salt for key derivation

Archive Validation

Before importing, Plugin Reporter validates:

  • File integrity (not corrupted)
  • Format version compatibility
  • Data structure validity
  • Password correctness (for encrypted archives)

If validation fails, Plugin Reporter will display a detailed error message.

Troubleshooting

Can't Open Archive

If you can't import an archive:

  • Verify the file extension is .pluginreporter
  • Check that the file isn't corrupted (try unzipping manually)
  • Ensure you're using a compatible version of Plugin Reporter
  • If encrypted, verify the password is correct

Wrong Password

If the password doesn't work:

  • Check for typos and capitalization
  • Try pasting the password from your password manager
  • Verify you're using the correct archive file
  • Important: There is no password recovery - if lost, the archive cannot be opened

Import Succeeds But Data Missing

If the import completes but data is missing:

  • Check if you chose "Merge" - your existing data is still there
  • Restart Plugin Reporter manually
  • Check Settings > General to verify data loaded correctly
  • Try "Replace All" mode instead of "Merge"

Archive Too Large

Archives are typically very small (usually under 1 MB), but if you have thousands of playlists:

  • Consider archiving selectively (feature coming soon)
  • Delete old/unused playlists before archiving
  • Large archives (even 10-20 MB) should work fine

Best Practices

Archive Safety Checklist

  • ✅ Create archives regularly (weekly or monthly)
  • ✅ Always use encryption for archives stored in the cloud
  • ✅ Test your archives by importing on a test account
  • ✅ Store archives in multiple locations (3-2-1 backup rule)
  • ✅ Keep archive passwords in a password manager
  • ✅ Name archives with dates for easy identification
  • ✅ Create an archive before major app updates or OS upgrades
  • ✅ Don't delete old archives - disk space is cheap!
